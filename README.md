# PACER: feedback and independent checks

A public place to question, check, and improve **Circuit-aware protection against burst errors in lattice surgery**, by Jaebum (Eric) Kim.

- Paper: https://arxiv.org/abs/2611.14583
- Frozen code/data archive: https://doi.org/10.5281/zenodo.24046121
- Research correspondence: erickim1492@gmail.com

This is a feedback repository. It does not contain the private research workspace or promise that every exploratory result is part of the paper. PACER's reported benefits are simulation results, not measured hardware performance.

## A small contribution is enough

- **Measurement or model correction:** identify the observable, preparation/readout sequence, source, and assumption it constrains. A source-backed explanation that a mapping cannot be made is useful too.
- **Proposed comparison:** name one change, the quantities held fixed, what the decoder knows, and what the test would distinguish.
- **Reproduction or artifact issue:** identify the exact archive/file/figure, environment, steps, expected result and observed result. Distinguish analysis of stored counts from regeneration of sampled trajectories.

Use an issue template for public discussion. Email is also welcome, especially for questions that should not be public. Please do not post credentials, private device data, or unpublished third-party material.

## What happens after feedback

Eric will assess the input against the cited evidence. An investigation can be documented with the result, remaining uncertainty, and any revised artifact. An unresolved or negative finding is a valid outcome. Credit will be agreed before attribution; opening an issue does not imply collaboration or endorsement.
